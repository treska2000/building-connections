# Калибровка τ₂/τ₃ для VPY — методология выбора порогов (Req 2, mode-2/3)

**Дата:** 2026-06-12 · **Код:** `req2_vpy_calibration.py` (один файл, MASTER_SEED=20260612, полный прогон ≈ 4–5 мин на ноутбуке) · **Числа:** `req2_vpy_calibration_results.json` · **Графики:** `vpy_calibration_plots/` · **Спека мод:** `req2_solvability_spec_2026-06-07.md` · **Образец методологии:** `morph_leak_report_2026-06-08.md`

Порог отвечает на вопрос на уровне ПУЛА: «достаточно ли пул богат ловушками и при этом однозначен, чтобы из него массово извлекались валидные доски?» VPY — не скор объекта, а биномиальная доля по N сэмплированным доскам, поэтому калибровка состоит из трёх независимых частей: (1) что VPY измеряет структурно, (2) где провести τ, (3) при каком N решению можно верить.

> **Главный вывод за 30 секунд.** Рекомендация: **τ₂ = 0.29, τ₃ = 0.66, N = 400**, зона неопределённости — Wilson 95% CI (±0.045 при p≈τ): если CI накрывает τ → вердикт **pending**, не бинарный. VPY-гейт обязан быть **составным**: `drawn ≥ 0.5·N` (голод сэмплера = fail) + контр-метрики структуры (`trapped_pairs_extractable ≥ 2`, `trap_terms ≥ 2`), иначе он обыгрывается минимизацией ловушек. Сам τ — НЕ разделяющая граница между «хорошо» и «плохо» (механизмы порчи коллапсируют VPY в ~0, зазор огромный), а **пол под слабейшим живым профилем**: τ = q05(слабейшего позитивного рецепта) − шум измерения. Ключевая структурная находка: VPY₂ определяется **максимальным пересечением одной пары** (o) и почти не видит остальной пул — поэтому константный τ осмыслен, но богатство ловушек τ не контролирует и контролировать не может. Абсолютные значения — синтетика: доверять относительным выводам, пересчитать при появлении живых goldens.

## 1. Рекомендуемая конфигурация гейта

| Параметр | Значение | Обоснование (раздел) |
|---|---|---|
| **τ₂** (`min_vpy_mode2`) | **0.29** | q05 слабейшего позитивного рецепта (good_rich, 0.3325) − Wilson-полуширина при N=400 (§4) |
| **τ₃** (`min_vpy_mode3`) | **0.66** | то же по good3_sparse (0.705); профиль mode-3 систематически выше mode-2 (§6) |
| **N** (`n_samples`) | **400** (800 для пограничных) | flip-rate ≤ ~0.08 у пулов в зоне τ±0.02; вне зоны ±0.1 — стабильно уже при N=100 (§5) |
| **min_drawn** | **≥ 0.5·N** | drawn=0/мало = голод сэмплера — это структурный fail, а не «нет данных» (§3, neg_deficit/neg_dense) |
| **Зона pending** | Wilson 95% CI ∋ τ → `pending` | при p≈τ полуширина ±0.045 (N=400); решение в зоне не воспроизводится между сидами (§5) |
| **Контр-метрики** (mode-2) | `trapped_pairs_extractable ≥ 2`, `trap_terms ≥ 2` | закрывают adversarial-минимизацию ловушек, которую VPY не видит (§7) |
| **Кросс-модовое И** (mode-3) | вердикт₃ = min(гейт₃, гейт₂ если в пуле есть overlap-материал) | decoy-кондиционирование маскирует порчу базы (§6) |

Предлагаемый фрагмент `thresholds.yaml` / `acceptance.yaml`:

```yaml
R2: { min_vpy: 0.70,
      min_vpy_mode2: 0.29, min_vpy_mode3: 0.66,
      n_samples: 400, seed: 42,
      min_drawn_frac: 0.5,                    # drawn < 0.5·N → fail (голод)
      pending: wilson95,                      # CI ∋ τ → pending, не pass/fail
      mode2_counters: { trapped_pairs_extractable: 2, trap_terms: 2 } }
```

`trapped_pairs_extractable` = число пар категорий с |a∩b| ≥ 1 **и** |a∖b| ≥ 4 ∧ |b∖a| ≥ 4 (пересечение есть И вокруг него извлекается доска). Считается по множествам, без solver — функция `structural_counters()` в коде.

## 2. Что VPY измеряет аналитически (E1, E1b)

### Механизм: swap-циклы

Кандидат mode-2 строится как корректная партиция (4×4 по member_of) с ≥1 ловушкой (термин с ≥2 тегами внутри S). Однозначность ломается, только если существует **альтернативное точное покрытие**, а оно требует цикла переброса: ловушка v∈A∩B уходит из квада A в квад B, и дыру в A закрывает другая ловушка той же пары. Следствия, подтверждённые эмпирикой (E1b, инструментированный сэмплер — rng-эквивалентен боевому, проверяется в selftest):

* **P(unique | ровно 1 ловушка на доске) = 1.0** — на всех профилях, без исключений.
* P(unique | 2 ловушки) ≈ 0.30–0.46; дальше падает с k (при k=6 → 0).
* Ловушки **разных** пар цикл не образуют: при o=1 VPY₂=1.00 везде, сколько бы пар ни было.

### Фазовая карта (e1_phase_vpy2.png)

VPY₂ — функция в первую очередь **o (макс. пересечение пары)** и запаса m−o; число пересекающихся пар n_pairs∈{1,2,4} на карте практически не меняет картину (кондиционирование кандидата локализует доску вокруг одной ловушечной пары):

| o | VPY₂ (диапазон по m=5..9, K=8) | режим |
|---|---|---|
| 1 | 1.00 | ловушки безопасны по построению |
| 2 | 0.54–0.71 | рабочая зона |
| 3 | 0.23–0.42 | граница фазы |
| 4 | 0.00–0.19 | обвал |
| ≥4 при m−o<4 | ∅ (drawn=0) | **голод сэмплера** — кандидат структурно не извлекается |

Обвал плавный по o, но **обрыв в ∅ — структурный**: вокруг ловушки нужно ≥4 непересекающихся термина на категорию (воспроизводит известный факт 5&5∩4 → 0 кандидатов; goldens — §8). Отсюда два вывода для дизайна гейта: (а) **τ как универсальная константа осмыслен** — механизмы порчи дают не «низкий», а коллапсированный VPY, и порог не обязан тонко резать середину; (б) τ должен быть функцией профиля пула только в одном смысле — **профили без запаса (m−o<4) вне области применимости VPY** (там вердикт даёт min_drawn, а не τ).

### mode-3 отличается по построению

VPY₃ = P(unique ∧ trap_quality≥1 | на доске decoy с целью из S). При честном decoy d→t квадры {d + 3 члена t} монохромны только через decoy-рёбра, поэтому tq≥1 выполняется почти всегда, и VPY₃ ≈ профиль однозначности, **систематически выше VPY₂** (носитель хороших: 0.70–1.00 против 0.27–1.00). Отсюда τ₃ ≠ τ₂ (§6).

## 3. Генеративные рецепты (E2): классы = механизмы, не значения VPY

Генератор `build_pool(K, m, pair_overlaps, triple_overlaps, decoy_spec, seed)`; рецепты сэмплируют параметры из диапазонов. 30 пулов/класс, чётные индексы → train, нечётные → **held-out test** (τ подбирается только на train). Метки обоснованы редакторскими механизмами (игровой дизайн), а не метрикой — оговорка о циркулярности в §9.

| Класс | Механизм | VPY₂ med (min–max) | drawn |
|---|---|---|---|
| good_sparse | 2–4 пары, o=1–2, запас ≥4 | 1.000 (0.53–1.00) | полный |
| good_rich | 3–5 пар, o=2–3, m=8–9 | 0.629 (0.28–0.70) | полный |
| neg_dense | o=4–5 при m−o<4 (плотное пересечение) | 0.000 | **0** (голод) |
| neg_dup | категория-дубль (делят m−1) | 0.000 | полный |
| neg_chain | треугольник A∩B∩C, o=3 + триплеты | 0.000 | полный |
| neg_deficit | мультитеговых терминов нет | — | **0** (кандидат невозможен) |
| neg_adversarial | ровно 1 пара ∩=4 при m=12–16 (минимум ловушек, pre2 проходит) | 0.449 (0.33–0.57) | полный |
| neg_adversarial_scatter | 4 разнесённых пересечения o=1, m=10–12 | **1.000** | полный |

Три негатива ловятся **разными частями составного гейта**: dense/deficit — голодом (min_drawn), dup/chain — порогом τ, adversarial — контр-метриками. Это не недостаток, а строение гейта: VPY-порог отвечает только за «ловушечный материал даёт однозначные доски».

Попутная находка про adversarial №1: текущее предусловие pre2 (∩≥4) **непреднамеренно мешает накрутке** — оно вынуждает держать 4 со-категорийных ловушки, доска часто содержит ≥2 из них → swap-циклы → VPY₂ всего 0.33–0.57, накрутить «почти 1» не выходит. Зато scatter (№2) набирает ровно 1.000 — см. §7.

## 4. Процедура выбора τ (E3)

Сравнивались три критерия (все считаются в коде, на train, adversarial-классы исключены из подбора — они по VPY неотличимы от хороших по построению):

1. **max-F1** → τ=0.01. Неинформативен: негативы коллапсируют в 0.0 (bad_max=0.0), любые τ∈(0, good_min] дают F1=1, и tie-break уезжает в вырожденный край.
2. **min τ при FPR≤5%** → τ=0.01. Та же вырожденность.
3. **q05 хороших − шум измерения** → **выбран**. τ = квантиль-0.05 **слабейшего позитивного рецепта** (не пула позитивов — иначе сильный подкласс маскирует нижний край слабого, и порог режет заявленный позитивный механизм целиком) минус Wilson-полуширина при N=400. Даёт максимальную строгость к невиданным промежуточным порчам при гарантии «не режем живое». Fallback в коде: если негативы подпирают (зазор < 0.05) — середина зазора; если разделения нет — max-F1.

τ₂ = 0.3325 − 0.046 → **0.29**; τ₃ = 0.705 − 0.045 → **0.66**.

**Held-out (вердикты pass/pending/fail; критерий приёмки):**

| Класс (test, 15 пулов) | VPY-гейт | + контр-метрики |
|---|---|---|
| good_sparse | 15 pass | 15 pass |
| good_rich | 13 pass / **2 pending / 0 fail** | то же |
| neg_dense, neg_dup, neg_chain, neg_deficit | **15 fail** каждый | то же |
| neg_adversarial | 14 pass (!) | **15 fail** (extractable=1 < 2) |
| neg_adversarial_scatter | 15 pass (!) | 15 pass (!) — см. §7 |

ROC/AUC=1.0 на разделимых классах — на авторской синтетике это ожидаемо и **не является свидетельством качества метрики**; содержательный результат — таблица выше и то, какой частью гейта ловится каждый механизм.

## 5. Статистическая надёжность (E4): N и зона pending

VPY — Binomial(N, p)/N, всё считается точно: полуширина Wilson 95% CI при p≈0.3–0.7 ≈ **±0.10 (N=50), ±0.07 (N=200), ±0.045 (N=400), ±0.032 (N=800)**. Аналитический P(flip) (вероятность встать не на ту сторону τ) и эмпирика по 12 сидам согласуются:

| p_true − τ | N=100 | N=400 | N=800 |
|---|---|---|---|
| ±0.02 | 0.30–0.36 | 0.18–0.20 | 0.10–0.11 |
| ±0.05 | 0.12–0.15 | 0.01 | ~0.001 |
| ±0.10 | ≤0.04 | ~0 | ~0 |

Эмпирически: пул с p_ref=0.306 при τ=0.29 флипается на 25% прогонов даже при N=400 и стабилен при N=800; пулы с |p−τ|≥0.07 стабильны уже при N=100–200.

**Правило:** N=400 по умолчанию; вердикт бинарный только вне CI — если Wilson 95% CI выборочного VPY накрывает τ, вердикт `pending` (эскалация: пере-прогон с N=800 или ручной разбор). Увеличивать N глобально бессмысленно: вне ±0.05-окрестности τ надёжность уже исчерпывающая, а внутри неё честный ответ — «на грани», что и кодирует pending.

## 6. Перенос на mode-3: τ₃ (E5)

Методология переносится без изменений процедуры, но **профиль другой** — и это надо фиксировать в гейте:

* Носитель хороших выше: good3_clean = 1.000 строго; good3_sparse 0.63–1.00 (q05=0.705). τ₃ = **0.66**. Нижний край определяет sparse-подкласс — VPY₃ наследует uniqueness-профиль базы.
* **neg3_leak** (decoy тайно член своей цели — испорченная разметка): trap_quality=0 → VPY₃=0.000 у всех 30 пулов. Ловится порогом идеально; это главный целевой негатив mode-3.
* **neg3_dense** (честные decoys поверх испорченной базы): VPY₃ med 0.246, но max **1.000** — кондиционирование на decoy-кандидатах **маскирует порчу базы**, если порченые доски не извлекаются (дубль-пара со совместной выборкой → None в `_draw_partition` → порченая область выпадает из выборки). VPY-гейт mode-3 пропускает 13% таких пулов (held-out). Закрытие: **кросс-модовое И** — для пулов с overlap-материалом (trapped_pairs_any ≥ 1) вердикт mode-3 = min(гейт₃, гейт₂). После этого held-out: leak 15/15 fail, dense 15/15 fail, позитивы — 27 pass / 3 pending / **0 fail**.

Вывод: τ₃ отвечает **только за качество обманок**; за чистоту базы отвечает mode-2/mode-1 гейт. Не пытаться грузить одну метрику двумя обязанностями.

## 7. Anti-gaming: способы накрутки и их закрытие

Генерация конфигов видит метрику и может оптимизировать пул под порог. Разобранные стратегии:

| Стратегия | Эффект на VPY₂ | Чем ловится |
|---|---|---|
| Минимум ловушек при выполнении pre2 ∩≥4 (adversarial №1) | 0.33–0.57 (накрутка не удаётся: ∩≥4 сам создаёт swap-материал) | `trapped_pairs_extractable ≥ 2` (у него ровно 1) |
| Разнесённые одиночные пересечения o=1 (scatter, №2) | **1.000** | **НЕ ловится** (см. ниже) |
| Дефицит ловушек вообще | drawn=0 | `min_drawn` + `trap_terms ≥ 2` |
| Разбавление чистыми категориями | не меняет VPY₂ (кондиционирование кандидата) | не требуется — метрика устойчива by design |
| Подбор seed | — | seed зафиксирован валидатором (42), не входом |

**Честно: что НЕ закрывается.** Scatter-пул (4 пересечения по o=1 при больших категориях) проходит τ, обе контр-метрики и даёт mean_traps_per_board 1.01–1.09 — но **good_sparse с o=1 имеет ровно те же значения по всем измеримым осям**. Это не дыра в пороге, а граница задачи: пул, «оптимизированный под порог», структурно совпадает с минимально-достаточным честным пулом. VPY-гейт enforce'ит **пол** (ловушки есть, однозначность есть, доски извлекаются), а не **богатство**. Если «одна безопасная ловушка на доску» редакционно недостаточна — это продуктовый порог на интенсивность ловушек (например, `mean_traps_per_board ≥ θ` — счётчик уже считается в `structural_counters`/`mean_traps_per_board()` без solver), и выбирать θ нужно из редакционных требований к сложности, а не из этой калибровки. Заметьте: при текущем pre2 (∩≥4) scatter отсекается предусловием — но тем же предусловием отсекаются и живые конфиги (§8); при рекомендованной замене pre2 на extractable-версию scatter легализуется. Этот трейд-офф решается только продуктово.

Арms-race-оговорка: контр-метрики тоже видимы генератору; следующая итерация атак (например, two-pair adversarial с ∩=4) пройдёт `extractable ≥ 2`. Устойчивая защита — не пороги, а то, что VPY сертифицируется CP-SAT-солвером на реальных досках: накрутить однозначность, не сделав пул фактически играбельным, по результатам E1/E2 не удалось ни одной из попробованных стратегий.

## 8. Sanity на реальных конфигах — не истина, а проверка «не отрезали живое»

| Конфиг | counters | VPY₂ (drawn) | вердикт₂ | VPY₃ |
|---|---|---|---|---|
| `_tmp_golden.json` (176 терм., 27 кат.) | extr=57, traps=85 | 0.695 (400) | **pass** | decoys нет |
| `config_v1_example.json` | extr=2, traps=3 | 1.0 (400) | **pass** | 1.0 → pass |
| `golden_ai-safety_v2.json` (5&5∩4) | extr=**0** | — (drawn=**0**) | **fail (голод)** | decoys нет |
| `golden_reasoning_v1.json` (5&5∩4) | extr=**0** | — (drawn=**0**) | **fail (голод)** | decoys нет |

**Прогон в боевом репо** (скрипт лежит в `validation/research/`, конфиги ищутся от корня): все **14 живых конфигов** `configs/v1/*.json` + `from-generator/*.v1.json` проходят mode-2 гейт с запасом — VPY₂ от 0.69 (`math_optimization_convexity`) до 0.96 (`ai_interpretability_mechanisms`), drawn=400/400, ни одного pending. Mode-3 ни на одном не определён: в конфигах нет `decoy_for_tags` — τ₃ начнёт работать после появления обманок (явных или margin-выведенных).

Порог не отрезает живые богатые пулы. Два тесных goldens ресёрч-папки (`golden_*_v2`, профиль 5&5∩4) фейлят не по τ, а по голоду — это та же эмпирическая находка 5&5∩4, теперь оформленная как вердикт, а не как тихий `vpy=null`. Два следствия: (1) **рассогласование спеки**: pre2 (`∩≥4`) проходит на пулах, где кандидат mode-2 структурно не извлекается, и наоборот — режет пулы с извлекаемыми ловушками o∈{1..3}; рекомендуется заменить pre2 на `trapped_pairs_extractable ≥ 1` (∩≥1 + запас ≥4 с обеих сторон); (2) goldens в текущем виде — не calibration-материал для τ₂ (mode-2 на них не определён); при пересборке закладывать запас m−o ≥ 4, лучше ≥ 5.

## 9. Чего методология НЕ гарантирует

1. **Абсолютные значения τ.** И рецепты, и метрика спроектированы одним автором; AUC=1.0 на такой синтетике — свойство конструкции, а не доказательство. Надёжны относительные выводы: иерархия механизмов порчи, форма фазовой карты, зависимость flip-rate от N. При появлении ≥10 живых конфигов с редакторской разметкой — пересчитать q05 по ним (правило выбора τ остаётся тем же).
2. **Богатство ловушек** (§7): floor-пул и scatter-атака неразличимы; нужен продуктовый порог.
3. **Полноту пространства негативов.** Закрыты 6 механизмов; не исследованы, например, смешанные порчи (dup + decoys-leak одновременно), несбалансированные размеры категорий в одном пуле, very-large-K (>30) режимы.
4. **Семантику.** VPY работает на графе принадлежности; категории-дубли *по смыслу* при разных терминах (R6/эмбеддер) и форменные лики (R3) он не видит — гейты других требований обязательны.
5. **Перенос τ₃ на margin-выведенные decoys.** Калибровка mode-3 сделана на явных `decoy_for_tags`; когда появится эмбеддерный вывод обманок (ε-полоса margin), распределение VPY₃ может сдвинуться — пересчитать E5 на том же коде.

### Когда методология неприменима (профили пула)

* m−o < 4 у всех ловушечных пар → mode-2 кандидаты не извлекаются, VPY₂ не определён (вердикт по min_drawn, не по τ);
* < 4 категорий размера ≥ 4 → сэмплеры неприменимы (это R1);
* decoy_pool = 0 → mode-3 не определён (n/a, не fail);
* пулы, где почти все термины мультитеговые (trap_share → 1, как `_tmp_golden`-стиль агрегаты с 27 категориями): VPY₂ остаётся определён, но интерпретация «пол под слабейшим живым» строилась на профилях K≤10, m≤16 — за их пределами сначала прогнать E1-карту на соответствующей сетке.

## 10. Воспроизводимость

```bash
pip install ortools          # CP-SAT; matplotlib для графиков
python3 req2_vpy_calibration.py            # полный прогон, ≈4–5 мин
python3 req2_vpy_calibration.py --fast     # смоук ≈1–2 мин
```

* Два независимых свежих прогона дают побайтово идентичный `results` в JSON (проверено; отличается только `meta.runtime_s`).
* Все rng — `random.Random` с seed'ами, производными от MASTER_SEED=20260612; CP-SAT — `num_search_workers=1`, перечисление с cap=2. LLM в контуре нет.
* Скрипт переиспользует `validation/solver.py` (или `validation_pipeline/solver.py`) — кандидатная логика инструментированного сэмплера проверяется на rng-эквивалентность боевому в selftest, известные факты (голод 5&5∩4; m=7/o=2 → VPY₂≈0.64 при заявленных ≈0.72 — тот же порядок, точная конфигурация исходного пула неизвестна) воспроизводятся там же.
* Тяжёлые блоки кэшируются в `.vpy_calib_cache_v2/` поэлементно (на числа не влияет; для пере-прогона с нуля — удалить кэш); `--time-budget S` позволяет прерывать/возобновлять длинный прогон.
